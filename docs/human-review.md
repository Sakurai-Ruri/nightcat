### A-2. npm 缓存放在项目外层目录（对设计文档的偏离）

- [ ] 认可这个做法，或改成我更喜欢的方式

**现状**：你机器的 `~/.npm/_cacache` 里有 root 属主的文件（历史遗留），npm 写入时报 `EPERM`。标准解法是 `sudo chown -R 501:20 ~/.npm`，**我没有执行任何 sudo**，而是把缓存改到 `夜猫子神器/.npm-cache`（仓库外层，已被 `.gitignore` 排除）。代价：每次在 `nightcat/` 里装包要带 `--cache ../.npm-cache`。

**为什么需要你决定**：修 `~/.npm` 权限是一劳永逸的，但需要你的 sudo 密码，且会改动家目录——这属于"你的机器你的规则"。

**若选择修权限**（之后 npm 命令就不用再带 `--cache`）：

```bash
sudo chown -R 501:20 ~/.npm
```

另有一个独立问题：npm 源是 `registry.npmmirror.com`（淘宝镜像）。这是你原来的配置，我没动。用镜像装包更快，但**依赖内容与官方源存在理论差异**。若你在意供应链一致性，可切回官源。这个也请你确认一下是有意设置的。

### A-5. 公开仓库还没有 LICENSE —— 需要你选一个

- [ ] 决定用什么许可证（或明确决定"暂不加"）

**现状**：仓库已在 https://github.com/Sakurai-Ruri/nightcat 公开，但**没有 LICENSE 文件**。

**为什么这是个真问题**（而不是走流程）：没有许可证的公开仓库，法律默认是"**保留所有权利**"。也就是说别人可以**看**你的代码，但不能合法地复制、修改、分发或在他们的项目里使用。GitHub 上的"fork"按钮虽然点得动，但严格来说没有许可证时 fork 出的副本属于灰色地带。

**三种常见选择**：

| 许可证 | 别人能做什么 | 适合什么情况 |
| --- | --- | --- |
| **MIT** | 几乎任何用途，只要保留你的版权声明 | 想让别人自由使用/学习/借鉴（最常见，个人项目首选） |
| **Apache-2.0** | 同 MIT，另含专利授权条款 | 想更严谨一点，或以后可能商业化 |
| **暂不加** | 谁都不能用，只有你能用 | 还没想好，或打算以后闭源/收费 |

**怎么做**（选 MIT 的话，30 秒）：

1. 打开 https://github.com/Sakurai-Ruri/nightcat/new/main
2. 文件名填 `LICENSE`
3. 页面右侧会出现 **Choose a license template** 按钮，点它 → 选 MIT → 填你的名字和年份 → 提交

**注意一个坑**：你现在在文档里写了"付费 AI 层"（V0.6 规划）。如果将来真的要做商业版，MIT 允许别人直接拿你的代码去卖。到时候要么换许可证（但已经发布的 MIT 版本无法收回），要么把商业功能放在单独的私有仓库里。这个决定现在不急，但值得现在就知道。

## D. 技术债与已知局限（不需要你现在做，但要知道它们存在）

- **夏令时**：`elapsedMinutes` 按本地时间字段直接相减，不补偿 DST 跳变，切换日可能差 1 小时。已在测试中显式钉住，见 D-010。
- **连续熬夜**：超过 24 小时不睡不会切分个人日。已在测试中记录。
- **`sleepTimeOfDay` 的 0 值歧义**：09:00 起床 + 9 小时睡眠时返回 `0`，无法区分"00:00"与"无值"。V0 不使用它的返回值，已加注释。
- **测试文件的三处重复**：`src/**/*.test.ts` 这个模式同时写在 `package.json`、`tsconfig.test.json`、`tsconfig.app.json` 三处，必须保持一致。见 D-012。

- **极昼/极夜**：`sunrise`/`sunset` 可能缺失，第 4 步需能表达"当日无日出"而不崩。见 D-010。
